# Build decisions

Decisions made while building the core app overnight (18 Nov 2026), for Julian to confirm or reverse. Source of truth for product behaviour is [`core-product.md`](core-product.md); where this file and the spec disagree, the spec wins and the code should follow.

| # | Decision | Why | Reverse by |
| --- | --- | --- | --- |
| 1 | App lives at the repo root, not `apps/mobile`. | One app, one `package.json`; a monorepo adds tooling with no second package to justify it. | Move into `apps/mobile` later; nothing depends on the path. |
| 2 | Persistence is Zustand `persist` on top of a `StateRepository` interface with an AsyncStorage implementation. No SQLite yet. | The whole hierarchy is small (tens of rows); one JSON document is simpler to sync later and works identically in Expo Go, dev builds and web. | Implement `StateRepository` with expo-sqlite or Supabase; screens do not change. |
| 3 | Speech-to-text is Whisper via `expo-audio` recording + OpenAI transcription, not `expo-speech-recognition`. | It works inside Expo Go tonight (no native module, no dev build). The build plan's on-device STT needs a development build; it slots in behind the same `SpeechInput` interface. | Add an `expo-speech-recognition` `SpeechInput` when the dev build exists. |
| 4 | Guide output is a `GuideProvider` interface with `MockGuide` (default, offline, rule-based) and `LLMGuide` (Anthropic, JSON via tool use; OpenAI for STT/TTS). `LLMGuide` falls back to `MockGuide` on any error or missing key. | The app must run with no keys and never block on network. | Set keys in `.env` to switch; see RUNNING.md. |
| 5 | Vendor calls go directly from the device using `EXPO_PUBLIC_*` keys, with an optional `EXPO_PUBLIC_GUIDE_PROXY_URL` that routes the same requests through a proxy. | Fastest path to a working personal build. Keys inlined in the bundle are acceptable for user zero on his own phone, not for testers. | Stand up the proxy (Supabase Edge Function per the build plan) and set the URL before TestFlight. |
| 6 | Near-term ideal scene horizon is **6–9 months** (spec §3), not the 3–5 years in the kickoff summary. It is one constant in `src/interview/script.ts`. | The spec is the source of truth. | Change `NEAR_TERM_HORIZON`. |
| 7 | Life goals must link to an ideal-scene passage. When the user types one freehand, the best word-overlap passage is attached automatically and shown; the user can change it. | Keeps the spec's "every goal threads to a scene sentence" invariant without forcing a picker on every entry. | Make the passage picker mandatory in the interview's life-goals step. |
| 8 | Level counts are targets, not gates: the interview needs at least 3 life goals and at least 1 goal per lower level to continue; it suggests the method's 10–12 / 5 / 3–5 / 3 / 3 / 3. | A 45-minute interview that refuses to continue is abandoned. The counts are visible as "N of M suggested". | Raise `LEVEL_TARGET.min` in `src/domain/levels.ts`. |
| 9 | Weeks run Monday–Sunday. Weekly Review on Saturday/Sunday closes the current week and plans next week; on a weekday it closes last week and plans this week. | A first review mid-week should still produce this week's priorities. | `resolveReviewWeeks` in `src/domain/dates.ts`. |
| 10 | "Carry" in Weekly Review marks the old action carried and creates an open copy under a priority in the new week. Dropped is a neutral terminal state. Nothing is deleted. | Keeps history for the course line and for the guide's drift detection; no red states. | — |
| 11 | No streaks anywhere. The day record stores started/closed timestamps and the user's sentences; nothing counts consecutive days. | "Course, not streaks". | — |
| 12 | Self-talk / reframe layer is a settings toggle (`selfTalkLayer`) that is off by default and exposes one optional prompt in Morning Course. Not built further in v1. | Spec: opt-in layer, not core. | Build the Catch and Reframe flow behind the same flag. |
| 13 | Method notes (`MethodNote`) are typed data in `src/content/methods.ts`, seeded from the product concept's evidence section; to be replaced by the spec's authoritative table when it lands. | Requested by Julian; content must be swappable without touching screens. | Edit `methods.ts`. |
| 14 | Navigation: three tabs (Today, Talk, Week) with Settings behind an icon on Today; Interview and Weekly Review are full-screen flows. | Build plan: no tab bar over three items. | — |
